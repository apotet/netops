## Конфигурация

Production workflow и до N5 запускал `npm run build -- --base=/netops/`. CLI-значение Vite имело приоритет над `vite.config.ts`. Теперь значение по умолчанию тоже `/netops/`, флаг Pages сохранён. Интерфейс использует вкладки и якоря, маршруты файлов начинаются с `/netops/`. При публикации workflow создаёт `release.json` и `.nojekyll` и проверяет, что ресурсы стартовой страницы присутствуют в сборке. Workflow Pages публикует только push в `main`.

Фото и шпаргалки идут из [закреплённого снимка общего репозитория](https://github.com/apotet/osi-tcpip-exam-public/tree/1c52fa81222167dc4377fe4788de86f3e36ad444). Проверено 90 путей фото, 14 форматов шпаргалок и файл атрибуции. Все 105 ресурсов вернули HTTP 200. Open Graph использует тот же снимок.

## Данные и откат

Формат статистики `osi_user_progress_v4` и оболочка последней попытки v1 сохранены. Новые production-попытки N5 сохраняются отдельно в `osi_active_session_netops_n5`; незавершённая попытка из общего ключа `osi_active_session` доступна отдельно и после явного выбора продолжает сохраняться в своём ключе. У всех 752 вопросов N4 есть те же ID в N5. Для 39 вопросов с изменённым условием, вариантами, ключом или изображением сохранены проверяемые данные N4. Восстановление сопоставляет текст, порядок и ключ с известным снимком. Разбор такого вопроса показывает прежнее пояснение. Повреждённое содержимое продолжает отклоняться.

Production и staging на `apotet.github.io` разделяют origin. N4 не читает отдельный ключ N5. Запуск или продолжение теста в N4 не заменяет новую попытку N5. После возврата на N5 оба совместимых сохранения видны независимо. Если более ранняя сборка N5 использовала общий ключ и N4 перенёс несовместимую попытку в резерв, N5 предложит явное восстановление проверенной попытки из той же эпохи прогресса, пока отдельный ключ N5 не занят. Восстановление не переписывает сохранение N4; исходная резервная копия остаётся в экспорте. Нечитаемое сохранение N5 можно заменить новым тестом только после явного подтверждения и успешной записи его копии для экспорта. Не очищайте данные браузера при откате: попытки не переносятся между origin/профилями. Сброс в N5 удаляет оба ключа, а смена эпохи при сбросе в N4 не даёт старому сохранению N5 возобновиться.

Изменения попытки принимаются только после успешной записи слота и проверки сохранённой копии. Неудачная или устаревшая запись не продвигает попытку и не добавляет статистику или разбор. Если попытка записана, а обновление статистики или разбора не удалось, N5 восстанавливает производные данные из сохранённых попыток при следующем открытии, без двойного учёта ответов. Новый тест не заменяет старую попытку, пока её единственное надёжное сохранение ещё нужно для такого восстановления.

Совместимые вкладки N5 выполняют запись попытки и восстановление под одним Web Lock. Старые версии и браузеры без Web Locks не участвуют в этой блокировке: для них проверка ожидаемой и записанной копий снижает риск конфликта, но не является атомарной операцией. Не ведите одну попытку одновременно в разных версиях или вкладках.

Если после будущего выпуска потребуется откат:

1. Сверить текущий production SHA через `/netops/release.json` и определить merge-коммит выпуска. Создать ветку от текущего `main`. Для обычного merge выполнить `git revert -m 1 <merge-SHA>`, для squash — `git revert <squash-SHA>`. Оформить отдельный rollback PR.
2. Если выпуск был единственным изменением с N4, сверить дерево rollback с `git rev-parse dc205a85d76e90d35fdcd20c5a1f11f48463ca2e^{tree}`. Если в `main` уже есть другие согласованные изменения, проверить их отдельно. При необходимости полного отката применить точный снимок N4 с его прежним инвентарём и workflow на отдельной ветке.
3. Запустить проверки rollback PR, включая сборку Node 22 под `/netops/`. После разрешения владельца слить rollback PR и подтвердить в Pages совпадение артефакта с восстановленным деревом. `release.json` должен содержать SHA нового rollback-коммита и прежний staging-источник N4. Повторить Chromium smoke и проверить сохранённую статистику. Историю `main` и теги не переписывать.

## Ограничения и материалы для приёмки

- [Desktop 1440](evidence/desktop.png) и [mobile 390](evidence/mobile.png) сняты на локальной сборке Chromium. Кандидат проверялся до публикации.
- Три старых дополнительных скрипта `l2-security.test.mjs`, `practice-links.test.mjs` и `study-text.test.mjs` воспроизводят расхождения и на исходном staging SHA. Первые два ожидают ранее добавленные ссылки на стенды, третьему нужен пересмотр исторического списка разборов. Проверки кандидата и соответствующие тесты релизного workflow сохранены. Эти несоответствия остаются явно открытыми для независимой приёмки.
- HTTP-проверка всех внешних ресурсов и декодирование в управляемом Chromium прошли. Изолированный headless Chromium отвергает сертификат облачного прокси на внешних хостах, поэтому проверки внешнего декодирования и локальных интерфейсов проведены раздельно.
- Сборка Vite выдаёт предупреждение о размере чанков. Доступ к живому Pages `release.json` из оболочки среды ограничен (HTTP 403). Проверка точного дерева отката выполнена локально.
